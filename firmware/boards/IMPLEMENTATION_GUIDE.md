# Implementing the board layer for edge-post

This guide shows how to implement `sensors.c`, `tcp_client.c`, `clock`, and
`main.c` for your STM32 board using the role macros generated from your
CubeMX `.ioc` file. Example reference implementations are provided in
`firmware/` (see `board_clock.c`, `board_sensors.c`, `board_tcp_client.c`,
`main.c`) and an example `board_config.h` is in `boards/example-board/`.

## Prerequisites

1. Your `.ioc` is placed at `firmware/boards/<board>/<board>.ioc` (local,
   Git-ignored).
2. CubeMX GPIO labels use the edge-post conventions:
   - `TEMP_` — temperature ADC input
   - `NET_` / `NET_CS` — W7500P network link (SPI or UART) + chip select
   - `OUT_` — controllable GPIO outputs
3. Run `make board` to generate `board_config.h` and `boards.json`.
4. Run `make BOARD=<board> board-select` to confirm the header resolves.

## Role macros your code uses

Generated by `make board` from `board_config.h`:

| Macro group | Example macros |
|-------------|---------------|
| Temperature | `BOARD_TEMP_ADC_INSTANCE`, `BOARD_TEMP_ADC_CHANNEL`, `BOARD_TEMP_ADC_PIN` |
| Network SPI | `BOARD_NET_SPI_INSTANCE`, `BOARD_NET_SPI_SCK_PIN`, `BOARD_NET_SPI_MISO_PIN`, `BOARD_NET_SPI_MOSI_PIN` |
| Network UART | `BOARD_NET_UART_INSTANCE`, `BOARD_NET_UART_TX_PIN`, `BOARD_NET_UART_RX_PIN` |
| Chip select | `BOARD_NET_CS_PIN` |
| Outputs | `BOARD_OUT_COUNT`, `BOARD_OUT<n>_PIN`, `BOARD_OUT<n>_LABEL` |
| Clock | `BOARD_RTC_SOURCE`, `BOARD_SYSCLK_HZ`, `BOARD_HCLK_HZ` |

All macros are guarded with `#ifdef` in the reference implementations, so the
code compiles even when a role is missing (the corresponding sensor/output
returns `SENSOR_ERROR_PIN`).

## Files to implement

### 1. `board_config.h` — generated, do not edit

`make board` writes this next to your `.ioc`. It contains only macros — no
logic. Your C sources include it via the board include path added by
`make BOARD=<board>`.

### 2. Clock (`board_clock.c` / `board_clock.h`)

Implements `device_clock_t` from `clock.h`:

```c
typedef struct {
    void *context;
    uint32_t (*now_seconds)(void *context);
    void (*sleep_ms)(void *context, uint32_t delay_ms);
} device_clock_t;
```

- `now_seconds` reads the RTC and returns Unix epoch seconds. Return `0` if the
  clock is unset (the app treats timestamp `0` as an error).
- `sleep_ms` blocks for at least the requested delay (e.g. `HAL_Delay`).

### 3. Sensors (`board_sensors.c` / `board_sensors.h`)

Implements `sensors_t` from `sensors.h`:

| Function | What it does |
|----------|-------------|
| `read_temperature_tenths` | Read ADC on `BOARD_TEMP_ADC_CHANNEL`, convert to tenths of °C |
| `read_gpio_state` | Return the GPIO output bitmask (bit n = pin n state) |
| `write_gpio_pin` | Drive `BOARD_OUT<n>_PIN` high/low |
| `set_sample_rate` | Store the sampling interval (1–255 s) |
| `get_sample_rate` | Return the current sampling interval |

### 4. TCP client (`board_tcp_client.c` / `board_tcp_client.h`)

Implements `tcp_client_t` from `tcp_client.h`:

| Function | What it does |
|----------|-------------|
| `connect` | Initialize W7500P (SPI or UART per `BOARD_NET_*`), connect to `CONFIG_SERVER_ADDRESS:CONFIG_SERVER_PORT` |
| `send` | Send a complete frame over the socket |
| `receive` | Wait up to `timeout_ms` for one complete frame |

### 5. `main.c` — composition root

Wires everything together:

```c
const device_clock_t *clock = board_clock_get();
const sensors_t *sensors = board_sensors_get();
const tcp_client_t *client = board_tcp_client_get();

app_result_t result = app_init(&app, CONFIG_DEVICE_ID, sensors, client, clock);

for (;;) {
    app_step(&app);
}
```

## Build

From `firmware/`:

```bash
# Generate board config from your .ioc
make board
make BOARD=<board> board-select
make board-check

# Build host tests (GCC/Clang, ASan/UBSan)
make BOARD=<board> test

# Cross-compile for your STM32 (example with arm-none-eabi-gcc)
make BOARD=<board> \
  CFLAGS+="-DCONFIG_DEVICE_ID=42 -DCONFIG_SERVER_ADDRESS=\"192.168.1.10\""
```

`CONFIG_DEVICE_ID`, `CONFIG_SERVER_ADDRESS`, `CONFIG_SERVER_PORT`, and other
`CONFIG_*` values come from compiler flags or `config.h` defaults — never from
the `.ioc` or tracked source.

## Adapting for your real board

1. Add `TEMP_`, `NET_`, `NET_CS`, `OUT_` labels to your `.ioc` in CubeMX.
2. Re-run `make board` and confirm `board_config.h` contains the role macros.
3. Copy `firmware/board_clock.c`, `board_sensors.c`, `board_tcp_client.c`,
   `main.c` into your build tree.
4. Replace the HAL adaptation stubs (marked with `/* HAL adaptation: ... */`)
   with calls to your part's HAL (STM32G0 HAL, W7500P driver, etc.).
5. Build and flash.

## What is NOT in these files

- No literal pin numbers or part numbers (they come from `board_config.h`).
- No server address or device ID (they come from `-DCONFIG_*` flags).
- No committed `.ioc`, `board_config.h`, or `boards.json` (all Git-ignored).
